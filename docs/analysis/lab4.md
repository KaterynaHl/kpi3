# Аналіз лабораторної роботи №4

## Що змінилося порівняно з лабораторною 3?

У лабораторній №3 система була побудована навколо CQS: commands, queries та handlers. У лабораторній №4 було додано міжкомпонентну комунікацію та integration events.

З’явився окремий Notification Component, який відповідає за побічні операції після бізнес-дій.

## Які побічні операції були виділені?

Було виділено notification component. Після створення поста система генерує повідомлення про створення нового поста.

Це хороший приклад side effect, бо notification не є частиною основної бізнес-операції створення поста.

## Синхронна комунікація

У синхронному варіанті `CreatePostCommandHandler` напряму викликає `NotificationService`.

Переваги:
- проста реалізація;
- легше дебажити;
- легше тестувати.

Недоліки:
- handler залежить від швидкості notification component;
- при падінні notification component може впасти вся операція;
- збільшується response time API.

## Асинхронна комунікація

У асинхронному варіанті handler публікує `PostCreatedEvent` у `EventBus`.

Notification component підписується на подію незалежно від command handler.

Переваги:
- менша зв’язаність;
- основна операція завершується швидше;
- side effects можна масштабувати окремо.

Недоліки:
- складніше тестування;
- складніше дебажити;
- eventual consistency.

## Порівняння підходів

| Критерій | Sync | Async |
|---|---|---|
| Response time | більший | менший |
| Coupling | сильніший | слабший |
| Failure handling | складніший | ізольований |
| Масштабування | гірше | краще |

## Який підхід краще для production?

Для production я б обрав asynchronous communication через event bus або message broker.

Такий підхід краще масштабується, зменшує coupling між компонентами та дозволяє незалежно розвивати side effects.

## Що буде при повторній доставці події?

Якщо подія буде доставлена двічі, notification handler може відправити повідомлення повторно.

Тому event handlers у production-системах мають бути idempotent — наприклад, перевіряти eventId або зберігати already processed events.
