# ADR 001: Використання Rich Domain Model

## Контекст

У лабораторній роботі №2 потрібно відділити бізнес-логіку від інфраструктури та обрати підхід до доменної моделі: Anemic або Rich Domain Model.

Доменом системи є платформа мікроблогінгу. Основна бізнес-логіка пов'язана з постами, коментарями та реакціями користувачів.

## Рішення

Було обрано Rich Domain Model.

## Чому було обрано Rich Domain Model

Rich Domain Model дозволяє розмістити бізнес-правила всередині доменних сутностей. Наприклад, `Post` сам контролює оновлення контенту, додавання коментаря та лайк. Це зменшує дублювання логіки в use cases і controllers.

## Наслідки

Переваги:
- бізнес-логіка локалізована в домені;
- простіше тестувати інваріанти;
- контролери не містять бізнес-правил.

Недоліки:
- більше класів;
- складніша структура;
- потрібен мапінг між шарами.
